# Reproducible PVM reference comparisons

## Scope and authority

The pinned Gray Paper in [protocol pins](pins.json) remains primary.
Pinned PolkaVM at `acff91f0df4494b576471feb0c031066ab7406df` supplies an
implementation cross-check through public APIs. The independent native implementation
and approved JAM compatibility exceptions remain unchanged. See the
[discrepancy register](graypaper-discrepancies.md) and
[upstream stack-clamp qualification](pvm-polkavm-stack-clamp.md). Historical receipts
and frozen fixture provenance retain their original source revisions.

`make check-pvm-reference` provisions the existing pinned Nimony/Rust tools and
sources, fetches the optional reference crate's locked dependencies, builds its
executables in release mode offline, then runs each reference probe and its matching
checked native suite. Ordinary native verification still consumes frozen fixtures
without requiring this optional Rust reference crate.

The [explicit backend contract](pvm-reference-backends.md) selects interpreter by
default or a strictly requested compiler, with no fallback. Parser/simulator-only
probes are declared backend neutral. Each reference executable owns a single `@@PvmReference` JSON comment naming its
native suite and optional input, generator or regenerated fixture. Discovery requires
every executable to declare a valid pairing. Unknown fields, missing native suites,
unsafe fixture paths and duplicate pairings fail before building. There is no
separate list of executable identities in the runner.

## Comparison coverage

| Reference probe | Native suite | Boundary checked |
| --- | --- | --- |
| Memory generator | `pvm_memory_boundary_reference` | Exact regenerated frozen bytes; scalar address/protection edges |
| `mixed` | `pvm_mixed_program_reference` | Complete memory/host/loop programs at exact, surplus and two underfunded gas boundaries |
| `memory` | `pvm_memory_access_reference` | Complete scalar forms, signed values, aliases and cross-page permissions with explicit GP-PVM-008 adaptation |
| `destination` | `pvm_destination_reference` | Complete three-register destination-byte values/prices, retaining explicit GP-PVM-009 raw/JAM rules |
| `registers` | `pvm_registers` | Independent arithmetic expectations, all posterior registers and trap PC |
| `gas` | `pvm_gas` | Independent GP block prices versus public pipeline simulator; native affordability/cycles |
| `control` | `pvm_conditional_control_reference` | Branch/load-jump programs, registers and exits with explicit PC representation |
| `jumps` | `pvm_jump_table_reference` | Raw paper versus JAM jump-table decoding and public module/execution observations |
| `validation` | `pvm_initialization` | Final-terminator admission matrix and prefix refusal |
| `cross_retry` | `pvm_metered_cross_page_retry` | Missing-page/read-only repair in one prepaid block, with exact/underfunded gas and atomic writes |
| `retry` | `pvm_metered_fault_retry_reference` | Fault, page repair and retry without duplicate gas charge |
| `hosts` | `pvm_metered_host_reference` | Two host exits, register replies and prepaid resumption |
| `limits` | `pvm_module_limits` | Complete code/count limits, including zero-width table normalization |

These are paired checks against shared fixtures or documented literal witnesses,
not a universal state-by-state adapter. In particular, the gas probe compares prices
through the simulator; the native suite additionally checks local cycle limits.
Native-only resource budgets and raw paper cases are not claimed as PolkaVM parity.
The runner preserves each probe's own output and assertions rather than interpreting
successful process termination as a claim of full PVM conformance.

## Evidence and failure behavior

Fresh evidence lives under `build/tests/pvm-reference/`: build, reference and native
logs plus `results.json`. The [Actions summary](pvm-reference-summary.md) presents
the same per-pair verdicts, with downloadable Markdown and raw JSON evidence. The report begins as running, records completed stages and
becomes successful only after every declared pair passes. Setup/provenance errors,
nonzero process exits, timeouts and mismatching regenerated bytes fail the run.
A timeout kills and reaps the owned process group, including compiler children.
Frozen inputs are never overwritten; regeneration uses the ignored output directory.

The report records the Git head, platform, specification/implementation pins, Rust
pin, crate lock digest, executable source digests and applicable fixture digests.
Each process retains its structured arguments, duration and exit status. Durations
are diagnostic timings, not comparative performance measurements. Native logs retain
the established checked release ARC/Clang LTO profile and fresh suite observations.
Source revisions and registry identities/checksums are checked before the build.

Harness controls exercise missing/unsafe declarations, duplicate pairings, nonzero
exit, timeout, stale-green replacement, build/reference/native refusal and a
successful generator producing wrong bytes. The local execution result is recorded
below only after completing the actual Make target; Linux CI is separate evidence.

## Readiness and later comparison work

The dedicated [Linux reference job](pvm-reference-ci.md) and broader
[mixed memory/host programs](pvm-mixed-program-reference.md) are implemented.
The [readiness map](pvm-interpreter-readiness.md) separates current fixture pairs
from future full upstream fuzzing. The existing positive gas-domain ambiguity remains
an explicit conformance gate. M1 framing is complete; complete state serialization,
whole-block parity and full chainspec equivalence remain open.

The maintainer requires future performance comparisons with one consolidated table:
workload, Ragnarök PVM, PolkaVM interpreted and PolkaVM compiled where supported.
Start with a meaningful common subset once its correctness comparisons pass; full
PVM completion is not a prerequisite. Validate equivalent results before timing,
record hardware/toolchain/source pins and execution profiles, separate preparation
or compilation from execution, and mark unavailable backends explicitly. The separate
[benchmark CI job](pvm-benchmark-comparison.md) is implemented with interpreted-only
measurements and an explicit deferred compiled column. The maintainer selected
the GitHub Actions run summary as the primary Markdown table, with downloadable raw
measurements and environment metadata alongside it. Do not split a
coherent table into one PR per result or backend.

The required [future fuzzing CI](graypaper-discrepancies.md#required-future-polkavm-fuzzing-ci)
remains a distinct job and coverage obligation. This deterministic runner does not
execute or claim the complete upstream Rust test suite or any fuzz target.

## Initial runner evidence (historical)

The complete Make target passed all nine declared pairs (one release build and
18 reference/native processes) on macOS with pinned Rust and checked Nimony
ARC/Clang LTO. This includes 38977 arithmetic rows, 1784 gas prices, 1800 control
paths, 90 frozen memory rows, 512 jump-table observations, the final-terminator
matrix, module limits, metered fault retries and host resumptions. The existing
probe-specific contracts describe the exact boundaries of those counts.
The runner controls, existing dependency-lock tests and Make harness tests pass.
No remote Linux execution, benchmark or fuzzing result is claimed.


## First limited speed baseline (historical)

The [consolidated benchmark](pvm-benchmark-comparison.md) now measures the verified
arithmetic, memory and host-loop subset with Ragnarök/interpreter/compiled columns,
explicit availability, raw samples and Actions summaries. This does not replace the
correctness runner or close the remaining conformance/fuzzing gates.

The backend-neutral [operand matrix](pvm-operand-reference.md) checks all thirteen
operand shapes through the public parser and both native owned decode profiles.
Its source declaration joins the ordinary discovery path; no new central dispatch
entry or upstream engine dependency is required.
