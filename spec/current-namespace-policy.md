# Explicit CLI namespace continuation policy

`download-current` accepts `--download-namespace-policy <file>` only alongside the existing `--download-logical-source` and `--download-logical-policy` pair. Omitting it retains strict identity-preserving behavior. The separate opt-in file uses exactly `ragnarok-current-namespace-policy-v1` and every leaf emitted by `encodeCurrentNamespacePolicy`: explicit full continuation limits, initial/continuation raw-storage and request capture, and independent selected storage/request/service history retention. No existing configuration is upgraded or assigned inferred resource defaults.

The existing logical policy still owns original source projection/profile/global/raw qualification. Namespace mode replaces its later `download.*` refresh budgets with the explicit continuation policy. Existing execution, created/deleted-account capture and storage limits remain in the main download policy; the supplement changes only its named namespace fields. Service history is optional, but storage/request histories must be explicitly enabled. Zero remaining caps retain their ordinary refusal/empty-work meaning. All policy and declaration transport/schema checks precede Services, database and outgoing peer startup.

Strict canonical decimal, bounded file/field extents, all required keys, unknown/duplicate/missing keys and overflow checks share the maintained v1 policy scanner. The successful result and failed field diagnostics are private and guarded. Both native input and logical source policy are frozen before worker borrowing; subsequent policy advancement retains mode and budgets.

Completion witnesses: every mandatory leaf omission, malformed/overflow/wide values, duplicate/unknown/version/cap and file boundaries, atomic option reparse, preserved independent execution fields, default source refusal, 1,000 ARC parser cycles, and actual authenticated TLS CLI mutation/adoption across three signed children on memory, disk and managed storage. Late policy refusal adopts no child; malformed supplemental policy starts no Services/database. Existing strict policies/source restart witnesses remain intact.

After namespace mutation, the original identity file is intentionally stale. This layer verifies strict physical reopen; exporting the latest genuinely adopted raw identities for a later logical restart is the next integration step. Database and identity export are separate artifacts; no storage or protocol wire format changes here. Full STF parity and the independent current-schema corpus remain separate gates.
