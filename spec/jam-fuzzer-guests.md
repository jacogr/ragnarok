# Nonempty guests through the JAM fuzzer interface

Authority remains GP `1fa8cbc7e7ec3e60d09f8e704911a89c6837ce1d` and the
unchanged davxy fuzz-v1 pin `acd4b2da310ff25226c4d41b918712578483fd2c`.
This increment executes the existing independently authored report/guest STF
references through the actual fuzz backend. It introduces no generated campaign,
upstream fixture change or relaxed GP predicate.

A shared exact-input replay driver receives independently calculated complete
seed checkpoints and signed blocks. Initialize transports the entire rootless
map under explicit bounds; ImportBlock uses the actual current candidate/PVM
pipeline. GetState uses the exact full sealed header identity. Expected maps and
roots are calculated by the independent references before native execution;
observed native results never calculate the next expected answer.

The report-to-guest corpus includes35 imports across five frozen chains and15
actual guest executions. Reporting, assurance release, grouped operands, storage,
yield and checkpoint/exceptional selection affect complete returned maps. Every
block also receives an invalid prior-root attempt, proving that failed imports
preserve the selected header and full state before the genuine block executes.
The original complete seed remains queryable after history-window eviction.

The `jam_fuzzer_` source-owned corpus declaration joins the existing Fuzz / JAM
job automatically. Live generated campaign validation remains pending a compatible
engine. Subsequent work extends effect families, exceptional/deferred behavior,
fork isolation and the separate seed header/state-clock compatibility boundary.

Storage/preimage coverage adds the complete frozen effect, request-lifecycle and
provision-lifecycle references:70 additional imports. Cases cover nonempty
preimage extrinsics, storage creation/replacement/deletion, panic rollback,
checkpoint retention, request creation/forgetting and selected queued provision
relevance/fulfillment. Every namespace byte, account footprint, C13 statistic,
C16 output and root is part of each whole-map comparison. The replay build is
shared across independent source-owned corpus declarations, preserving separate
inputs, logs and verdicts. Observation-only references are selected explicitly;
unsupported or incomplete streams still fail closed.

Transfer coverage groups direct, supervised and forwarded delivery with funding
pools, admission/gas boundaries and ordered memo effects. Six independent frozen
references contribute168 complete-map imports. Incoming/outgoing amounts, queued
and immediate delivery, recipient thresholds, gas costs, memo-selected storage,
checkpoint/panic selection, service balances, statistics and outputs are compared
through the actual fuzz backend. Each invalid prior-root attempt must leave the
entire selected state untouched before the genuine transfer-bearing block runs.

Account lifecycle coverage groups creation, code upgrades, incarnation-bound
supervision, retirement/refunds and manager handoff. Five independent references
contribute150 complete-map imports through the fuzz backend. Selected and rolled
back account/request namespaces, balances, newly derived IDs, privilege state,
code availability, statistics and outputs remain part of the exact returned map.
Repeated report releases exercise the selected code and authority in subsequent
blocks rather than checking an isolated host-call result.

Privileged role coverage groups full authorization queues, assigner/manager
precedence, validator designation and rotation, nonempty bless allowances,
revocation and incarnation eligibility. Six frozen references contribute202
complete-map imports. Local test-host ceilings explicitly admit4096-byte code
preimages and2560-byte queue copies. The protocol code-size gate remains separate:
authored4096-byte eligible-code profiles and the512-byte oversized-code control
retain their exact independently configured Parameters.

Replay may carry a full canonical122-byte host Parameters tuple alongside each
seed in its local test input. These trusted host settings never enter fuzz-v1
Initialize bytes and are never inferred from state contents or roots. Profile
counts and widths are checked before native execution, and each new chain resets
to its declared host configuration. This keeps code eligibility, resource policy
and actual GP validation distinct while comparing all posterior privilege,
authorization, roster, account, gas/statistics and output bytes.

Supervised foreign-effect coverage adds160 full-map imports for foreign storage,
request/provision changes, code upgrades, conflict selection and supervisor
handoff. The selected namespace version, checkpoint/panic outcome, foreign versus
self modified sets, incarnation authority, balances, statistics and output roots
are all observed through exact-header GetState. Existing independent references
and fixtures remain unchanged; no special execution or GP-validation path is used.

Funding and incarnation coverage groups reserved-ID creation, executable child
readiness, funded retirement/recreation, foreign creation/transfers, incarnation
authority and queued old-incarnation reports. Eight frozen independent references
contribute321 complete-map imports. Funded profiles explicitly retain their
7/1/100 deposit Parameters; zero-deposit profiles retain their original tuple.
The full maps include selected source pools, reserved IDs, account footprints,
refunds, replacement code, stale authority and reports queued before recreation.
