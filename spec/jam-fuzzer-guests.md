# Nonempty guests through the JAM fuzzer interface

Authority remains GP `1fa8cbc7e7ec3e60d09f8e704911a89c6837ce1d` and the
unchanged davxy fuzz-v1 pin `acd4b2da310ff25226c4d41b918712578483fd2c`.
This increment executes the existing independently authored report/guest STF
references through the actual fuzz backend. It introduces no generated campaign,
upstream fixture change or relaxed GP predicate.

A shared exact-input replay driver receives independently calculated complete
seed checkpoints and signed blocks. Initialize transports the entire rootless
map under explicit bounds; ImportBlock uses the actual current candidate/PVM
pipeline. GetState uses the exact full sealed header identity. Expected maps and
roots are calculated by the independent references before native execution;
observed native results never calculate the next expected answer.

The report-to-guest corpus includes35 imports across five frozen chains and15
actual guest executions. Reporting, assurance release, grouped operands, storage,
yield and checkpoint/exceptional selection affect complete returned maps. Every
block also receives an invalid prior-root attempt, proving that failed imports
preserve the selected header and full state before the genuine block executes.
The original complete seed remains queryable after history-window eviction.

The `jam_fuzzer_` source-owned corpus declaration joins the existing Fuzz / JAM
job automatically. Live generated campaign validation remains pending a compatible
engine. Subsequent work extends effect families, exceptional/deferred behavior,
fork isolation and the separate seed header/state-clock compatibility boundary.
