# Managed retained logical proof submission

`Services.beginLogicalProof` accepts explicit initialized retained logical provenance, a mixed
state proof plan and independent `LogicalProofLimits`. It uses the existing managed proof worker,
RPC pause and actual ticket collection/join path. It can prove an actual prepared successor before
canonical installation; it does not select a canonical head or authorize adoption/root trust.

Closed and scalar busy exclusions precede source access. Invalid source, selected-view admission
and original query failures remain guarded `CaptureFailure` alternatives. Existing managed RPC
pause/native admission causes remain `AdmissionFailure`. Capture activation aliases retire before
submission; all external source/plan aliases must stay untouched through cancellation and Done.
Only exact collection or joined shutdown restores access. Response bytes remain detached and must
be authenticated against a separately selected expected root.

The native positive control uses genuine Services current preparation/collection and complete
supplied qualification. It proves all sixteen chapters plus present-empty/absence values on an
uninstalled successor, verifies independent capture refusals, stale-ticket exclusion, cancelled Done,
worker reuse and joined shutdown, then authenticates detached bytes. Strict runtime and compiler
probes guard the new admission result. No worker transitions, RPC method/schema, storage format,
source pins or producer mutation provenance contract changes.
