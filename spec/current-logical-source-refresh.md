# Refreshing a logical identity source after downloads

`--download-update-logical-source` explicitly replaces the already supplied logical source file with identities from the last genuinely qualified adopted state. It requires the existing logical source/policy pair and works with strict or namespace continuation. No arbitrary new output target, storage format, root trust or recovery authority is introduced.

The command retains a logical owner only after matching successful adoption has retired native graph leases. On exit, transport and workers join before inspecting the actual canonical state and full selected view/Parameters. Export requires exact physical-state and complete-view agreement with that retained logical producer. Services then closes before bounded synchronous file IO. Failed later child attempts can still refresh the confirmed prefix; no unadopted candidate is exported.

The existing identity-only v1 exporter supplies canonical complete text under the selected projection's service/fact/per-key ceilings. Half its explicit byte budget, capped at the existing 64KiB source transport limit, bounds text plus native byte copy. The shared v1 parser/export ceiling also refuses raw keys above4KiB before file publication. Whole text planning precedes allocation and file creation. Existing atomic replacement synchronizes the file, renames a private sibling and synchronizes its directory. Ordinary failure preserves the previous file; visible-but-unsynced publication has a distinct failure status. Confirmed canonical progress remains visible in every outcome.

The database and identity file are separately durable artifacts. A crash between their publications can leave a stale source, which whole-source qualification refuses on restart. A canonical child confirmed only during joined shutdown uses its own [retained logical receipt](current-logical-shutdown.md). `closeAndCaptureLogical` joins borrowers, consumes its actual handoff and returns a receipt only when the child, canonical physical state and complete selected view/Parameters match. The command refuses to export a stale previous logical owner when those bindings differ. This completes the shutdown-receipt integration without making the database and identity file one atomic durable artifact.

Native completion witnesses extend actual authenticated TLS command tests with mutation/source refresh on memory, journal and managed backends, logical disk restart from the newly exported identities, a failed later child followed by restart from the refreshed durable prefix, and a real readable descriptor-path source whose atomic parent cannot accept publication. Exact4KiB raw-key export and logical restart succeed; a genuine4097-byte PVM key remains valid logical state but reports export refusal and preserves the previous source. Publication failure keeps the original source bytes and reports the already installed prefix. Existing strict source/parser/policy and physical reopen controls remain in the suite. The identity file is a companion to the selected state database and contains no payload backup.
