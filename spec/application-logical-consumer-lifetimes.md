# Logical consumer lifetime composition

The native consumer-scopes witness captures checkpoint, original-current review and bounded generic
proof query from genuine collected supplied qualification. After all native fixtures, logical/source
owners, query, capsule and review retire, detached checkpoint/proof bytes still decode against the
independently retained expected posterior commitment and original fixed schema. Every chapter is
typed/authenticated and checkpoint reconstruction matches that same expected commitment. Bytes
never establish their own trust. Plain ARC capture/drop remains host-only outside actual worker
leases; retained predicate identity and raw-key companion identity stay separate.

The retained-leases native suite keeps frozen supplied plans and logical consumers untouched across
real fixed-address preparation and proof workers. Both cancellation and Done retain exclusion until
matching collection; stale/default tickets cannot release it. Separate joined shutdown paths retire
queued/running/Done work before reusing the same plan. A 1,000-cycle ARC workload checks allocation
stability across both actual native worker lifecycles, with host-only source access between leases.

The combined native preparation/proof lease witness runs 1,000 cancelled-Done collection cycles
and verifies plan reuse after each actual matching collection and joined shutdown. It does not
claim whole-process allocation equality: pinned `getOccupiedMem` observes the calling thread's
allocator, whose foreign frees are accounted for on later allocations. Diagnostic samples after
successive 1,000-cycle batches oscillated (327,296; 327,920; 326,336; 326,992; 327,664 bytes).
Those samples neither prove a leak nor establish process-wide release. Existing isolated host-side
ARC witnesses retain their exact equality assertions; this workload establishes lifecycle behavior.
