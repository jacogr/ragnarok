# Logical receipts from joined download shutdown

`closeAndCaptureLogical` joins proof, disk-publication and preparation borrowers before retaining any logical alias. It then retires callbacks/input and consumes only its own actual handoff. A logical receipt leaves close only when the consumed successful adoption child, exact canonical physical snapshot and complete selected view/Parameters match the retained qualified producer. Default, pending cancellation, raw adoption and failed qualification expose no successful logical prefix. Ordinary `close` preserves compatibility by discarding the detached result after joined retirement.

This closes the gap where durable IO could finish after the last dispatcher tick: close already installed that actual child, but previously discarded the corresponding qualified logical owner. The command now retains the joined receipt before comparing its settled canonical prefix, so explicit identity-source refresh can use that exact installed source. State and identity file remain separate durable artifacts; no storage format or root-trust behavior changes.

Lifecycle hypothesis: publication completes while the host has not collected its Done receipt; joined close installs the canonical child and destroys the session's logical result before the caller can export it. The boundary is selected deterministically in native tests, so timing exploration is unnecessary. No model-checker verdict or new protocol interpretation is claimed.

Native completion witnesses use real TLS, actual original logical qualification and native workers across memory/journal/managed backends: queued but unexecuted cancellation; IO Done with its lease retained until close; installed-but-unconsumed handoff; already observed adoption; real raw adoption; and actual qualification refusal. Returned owners retain exact state/view/child binding and remain exportable after Services retirement and strict disk reopen. Explicit native IO shutdown preserves the existing requirement to restart Services before more execution/proof work, even when its completed receipt is durable. Closing again exposes no second/stale source, and the default result guard has an independent healthy control. Existing CLI source-refresh/resume and current dispatcher suites remain regressions.
