complete-inventory account predicates and selected economic profile. No new
protocol rule, RPC/Services integration, root discovery or storage format.

`planAccountReview` first requires a valid explicit economic profile and admits
the complete account audit policy. It then builds the bounded directory, checks
dependent footprints, and completes supervision/economic reports without payload
hashing. Every original typed failure is preserved under its guarded preparation
stage; no earlier prepared source/report prefix escapes refusal. Economic
undercoverage remains a successful observation. Arithmetic overflow can refuse
preparation before account content work, without inferring universal funding.

Success privately retains one original complete inventory, copied policies,
checked footprint evidence, and immutable same-source reports. `reviewPlanInfo`
returns copied observations only for an initialized plan. Execution accepts only
the frozen plan: linkage precedes content hashing, then same-owner invariant and
review joins complete. There is no substituted source/profile/quota argument and
no redundant footprint pass during execution. Failed execution exposes no review.

These synchronous operations retain the existing canonical ARC scheduling
responsibility. They perform no new worker operation or adoption. Existing
checkpoint review semantics remain unchanged; whole-state/STF parity is separate.

Completion requires selected native success/phase/refusal/backend cases, frozen
policy/owner tests, 1,000 ARC cycles, exact runtime guards with a genuine control,
and private/nominal compiler rejection checks. Run
`make unit SUITE=state_account_review_plan`.
