## API and ownership

`prepareContinuationAccumulationInvocation` accepts a genuine prepared continuation, nominal
service ordinal, service resolution policy and collision-probe ceiling. It resolves service code
and inputs from the retained actual posterior map. It follows the completed source to the original
block stage and decodes its exact 128-byte entropy chapter. The first entropy word feeds the
existing Psi_A bootstrap together with the authenticated slot and selected report-only inputs.
There is no caller-supplied entropy or service projection to replace those sources.

`bootstrapProjection` retains the existing pure invocation for bounded machine initialization;
`bootstrapContinuation` retains the genuine continuation source. Their owner is private, immutable
and acyclic. Failed/default results contain only the selected reason. `serviceError` and
`invocationError` enforce their corresponding result alternatives, preserving actual resolution,
code eligibility, hash-provider and probe-exhaustion refusals without partial owners. Unreachable
missing/malformed stage entropy remains a typed defensive refusal rather than a fallback.
