# Reusable collected logical refresh plans

Plan both configured-origin and completed-origin identity-preserving refresh after actual matching
preparation collection. The plan retains original identity/key/reconstruction/full-qualification
preparation, actual producer and copied policies. Its guarded failure returns the original selected
receipt or stage reason. Defaults grant no plan.

Execution accepts only that plan and rechecks the exact canonical prior before full payload/raw-key
matching. Backend failure permits retry without rebuilding request-key preparation. Later caller
policy changes have no effect; actual adoption makes the frozen plan stale. The existing one-shot
API delegates to these same phases, preserving original typed failure behavior. Services guards
both source alternatives and execution through all existing native graph leases.

Native coverage uses genuine collected first and subsequent children, both original source forms,
backend refusal/retry, request-budget failure, unchanged canonical state before separate installation,
default receipt/plan refusal and stale execution. Private/result and all-lease probes accompany the
feature. No producer mutation certificate, worker transition, storage/RPC format or pin changes.
