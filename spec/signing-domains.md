# Signing-domain token audit

Gray Paper **0.8.0**, revision `07f041dabd073f9018b418e9ee72e79dd2185401`,
`text/reporting_assurance.tex` equations `assurancesig` and `guarantorsig`, defines the assurance
and guarantee signing transcripts. [Closed issue #509](https://github.com/gavofyork/graypaper/issues/509)
and its [reply](https://github.com/gavofyork/graypaper/issues/509#issuecomment-3706909013) clarify
that `$` denotes a binary string and is not part of the token bytes. No dependency pin changes.

## Confirmed implementation defect and correction

Both implemented Ed25519 transcript builders incorrectly included a leading dollar byte.
Independent verification of published credentials confirmed the defect before production changes:
OpenSSL verified ASCII-domain messages and rejected dollar-prefixed messages for both tiny/full
assurances and reports. The corrected owned messages are exactly **45 bytes**:

| Builder | Exact message bytes |
| --- | --- |
| `assuranceMessage` | ASCII `jam_available` (13 bytes) followed by Blake2b-256(parent hash32 || fixed profile bitfield) |
| `guaranteeMessage` | ASCII `jam_guarantee` (13 bytes) followed by Blake2b-256(complete canonical report bytes) |

The digest starts at byte offset 13. There is no terminator, count prefix, implicit second hash,
slot/validator-index field or alternate-domain acceptance. The nominal public fixed-array widths
change from 46 to 45 accordingly; every verifier, driver and result-access probe uses that width.
Codecs, cryptographic primitives, exceptional-point acceptance policy and state-transition logic
are unchanged. Credentials signed using the old byte strings are intentionally rejected.

All four exact Git blobs have SHA-256 pins in [pins.json](pins.json). The fixture helper transports
original public keys/signatures, fixed bitfields and independently reconstructed report/message
bytes. It does not replace upstream credentials with signatures generated by this implementation.
Native `signing_domains` checks **all 1,035 credentials**, every expected message byte, digest
mutation rejection and rejection of each published signature over the old dollar-prefixed message.
For assurances, it also invokes the production contextual verifier using each original validator
index and the complete key table. These are transcript/signature checks, not full STF execution.

OpenSSL independently verifies the first and last credential from each source (eight credentials,
16 positive/negative domain verdicts) during fixture preparation. Native verification checks every
credential. This avoids thousands of redundant process launches while retaining an independent
provider witness for both profiles/domains. Provider version, source identities, counts and exact
fixture hash are retained in the ignored preparation manifest.

The existing **2,087 assurance-context** requests and **63 report-composition** cases retain their
count, structural/context boundaries and positive/negative workloads. Old dollar-prefixed signing
is now a negative credential instead of the positive baseline. Hashlib/OpenSSL fixture messages
and the 45-byte native known answers are updated together. New published signatures prevent the
local generator and production implementation from sharing this interpretation error again.
The existing observer/ARC result and backend refusal/recovery checks remain active.

## Audit scope and remaining work

The implemented signing-message constructors are the two above. Bandersnatch primitives accept
explicit raw caller contexts and do not compose further JAM signing domains. Future ticket,
seal, entropy, judgment and BEEFY compositions need their own exact-token vectors; their absence
is not full cryptographic protocol coverage. Existing immutable ownership and result contracts
remain intact.

JAMNP-S certificate names use separately specified strings/alphabet in `vendor/jam-np/simple.md`.
They are outside this signing-transcript correction and need a dedicated external-interoperability
review; this audit does not justify stripping `$` globally. [Open Gray Paper PR #549](https://github.com/gavofyork/graypaper/pull/549)
remains a future Merklization-upgrade question, not an adopted hashing change.
