# M1 codec progress

Target: Gray Paper 0.8.0 and published `davxy/jam-test-vectors` v0.8.0, at the exact revisions in
`spec/pins.json`. The **C.1/C.2 framing baseline is implemented within the schema scope below**.
This is not complete state serialization or a production-client milestone. Published codec samples
are syntactic fixtures; this project also enforces the documented canonical/structural policies,
without claiming complete state-transition or cryptographic eligibility from decoded values.

The maintainer wants manageable chunks of related functionality. Complete a coherent group,
report tested results, then wait for the next go-ahead. Do not equate one passing sample or one
round-trip with completion of a codec family.

## Scope boundary and next decision

The concrete C.2 gaps identified in the [coverage audit](codec-coverage.md) are now covered.
General collections support the explicitly documented value-only scalar families; arbitrary child
schemas need explicit adapters and ownership contracts. State-layout extensions cover keys, node
encodings and bounded roots over already serialized key/value entries. State-component groups
cover chapters 1–16 under the recorded encoding policies. The maintainer accepts the published
[compact C13 gas representation](../spec/state-statistics.md), with no fallback; its difference
from T's general width note is documented. The
[request-namespace question](../spec/state-clarifications.md) remains parked for Gray Paper
0.8.1/0.8.2 review and still qualifies full state parity. Further implementation scope will be
chosen separately with the maintainer.
The [namespace review](../spec/request-namespace.md) finds funded small-payload local witnesses,
so the inspected predicates do not justify excluding the overlapping lengths.
The [pinned width investigation](../spec/state-widths.md) supports the completed C12 E4/E8 and
C13 E4-key migrations. The request-namespace question remains parked.
[Typed state composition](../spec/state-composition.md)
now checks exact chapter extents, profile identity, parent budgets and all duplicate keys.
[Published full-map root evidence and the audit](../spec/state-roots.md) now cover fourteen unchanged
pre/post mappings; all fourteen also pass complete composition through validated chapter snapshots, typed
metadata and explicitly opaque service values. Full T(state) parity remains open.
Proofs/persistence, PVM execution and transitions remain future work.
The next scope requires a maintainer go-ahead.
Linux CI still needs to confirm each pushed increment; local passing tests are not a CI result.
