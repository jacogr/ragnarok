# Command line

Run `ragnarok --help` for grouped shared settings and the command list. Use
`ragnarok server --help` or `ragnarok help server` for the networking inputs and
service options accepted by that command. `ragnarok tiny-devnet --help` lists its
subcommands. No arguments show the overview, except when the public `JAM_FUZZ`
environment explicitly activates conformance. Explicit help never starts services.

A bare foreground server starts with local defaults:

```sh
build/ragnarok server
build/ragnarok server --with-ui
build/ragnarok server --data-dir ./another-node --net-port 34101
```

The server listens on UDP `34100` until SIGINT/SIGTERM. On first startup it creates
an Ed25519 TLS identity under `./data/network`: `key.pem`, `cert.pem`, and the raw
32-byte `public.key` used by `--net-peer-key`. Keys are private, generated by the
bundled TLS library, and reused on restart. Existing or partial identities are
never silently replaced. Supply both `--net-cert` and `--net-key` to use an
existing identity. Help and invalid CLI input create no files.

| Setting | Default |
| --- | --- |
| Data root | `./data` (`--data-dir`) |
| Network port | `34100` |
| Network protocol | `jamnp-s/1/00000000`, the isolated development domain |
| Server mode/deadline | `listen`, unlimited (`--net-timeout-ms 0`) |
| Client / bounded workloads | `valid` / 10000 ms |
| Full journal database | `./data/full/state.db` |
| Full managed / paged database | `./data/full/managed` / `./data/full/paged` |
| Light database/layout | `./data/light/paged`, `paged` |
| Management socket | Absolute path to `./data/management/admin.sock` |
| State / telemetry chain file | `./chain.json` when enabled |

Port inventory (services still require their `--with-*` flag):

| Endpoint | Transport / scope | Default or selection |
| --- | --- | --- |
| `--net-port` | UDP peer listener or remote peer | `34100` |
| `--net-local-port` / `--net-remote-port` | UDP mesh local / remote peer | `34100` / `34101` |
| `--with-ui`, `--ui-port` | HTTP, loopback | `8418` |
| `--with-rpc`, `--rpc-port` | WebSocket, loopback | `9418` |
| `--with-mcp`, `--mcp-port` | HTTP `/mcp`, loopback | `14141` |
| `--devnet-base-port` | Six consecutive UDP validator ports | Explicit base; `tools/tiny_devnet.py` selects a free range |
| `--telemetry-endpoint` | Remote collector | Explicit `HOST:PORT`; no local listener |
| `--management-socket` | Local Unix socket | No TCP/UDP port |

The browser derives its initial RPC endpoint from the shared RPC default and the
page hostname. Custom RPC ports can be entered in its connection field.

`--data-dir` relocates identities, inferred database paths and the management
socket. Explicit paths take precedence. State remains in memory unless disk is
selected; no directory setting enables a service. Disk startup creates parent
directories and keeps full/light nodes and physical layouts separate.

Chain specifications, remote pinned identities, light trust/header inputs, and
execution/download policies remain operator supplied. No chain or trust anchor
is generated. Select a real network explicitly with `--net-alpn`; the default
listener is the existing development transport, not a production validator.
Bounded harness workloads select `--net-mode valid` or another workload explicitly.

Every command value has a named flag. Positional forms are rejected, and flags may
be interleaved after the command. Networking settings use `--net-*`; downloads,
traces, development validators and conformance use their respective `--download-*`,
`--trace-*`, `--devnet-*` and `--fuzz-*` prefixes. `--net-cert` and `--net-key` are the
local TLS certificate/private key; `--net-peer-key` selects the pinned peer identity.
`--net-local-key` selects the separate mesh identity. Keep these key roles distinct.

```sh
ragnarok server --net-port 4000 \
  --net-cert node.cert.pem --net-key node.key.pem --net-peer-key - \
  --net-alpn "$configured_alpn" \
  --with-ui --ui-port 9000 \
  --with-state --chain chain.json

ragnarok download-current --net-port 4001 \
  --net-cert node.cert.pem --net-key node.key.pem --net-peer-key peer.pub \
  --net-alpn "$configured_alpn" --net-peer 4002:another-peer.pub \
  --download-policy current-policy.conf --download-blocks 2 \
  --with-state --chain chain.json

ragnarok check-traces --trace-policy current-policy.conf --trace-genesis genesis.bin \
  --trace-file step-0.bin --trace-file step-1.bin \
  --with-state --chain chain.json

ragnarok tiny-devnet node --devnet-dir data --devnet-index 0 \
  --devnet-base-port 4000 --devnet-start-unix-ms "$start_ms" \
  --devnet-stop-slot 4 --devnet-policy current-policy.conf
```

`--with-ui`, `--with-rpc`, `--with-management`, `--with-telemetry` and `--with-state`
appear before their settings in help. Configuring an endpoint, path or port does
not enable its service. UI also enables RPC. Help shows required fields and
resolved defaults; defaults are defined in `src/app/cli_defaults.nim`, with the
shared diagnostic threshold owned by `src/lib/logging.nim`. Conformance has its own
write budgets rather than borrowing execution defaults.

Repeat `--trace-file FILE` in execution order, `--download-ancestor FILE` newest
first, and `--net-peer PORT:KEY_FILE` for additional peers. Other flags are unique.
`--name=value` is accepted for value options. Remote identities, trust anchors and execution
policies have no inferred substitutes. Unknown flags, missing values, wrong-command flags and mixed bare
values are refused before networking or file IO.

Only the advertised canonical option names are accepted; legacy aliases and
positional command forms are rejected. Internal component fixtures receive normalized
command values through `parseCanonicalOptions`; process input must go through the
strict `parseOptions` boundary.

Conformance can still be launched with only the official environment variables:

```sh
JAM_FUZZ=1 JAM_FUZZ_SPEC=tiny JAM_FUZZ_DATA_PATH=/tmp/fuzz-data \
  JAM_FUZZ_SOCK_PATH=/tmp/fuzz.sock ragnarok

ragnarok fuzz --fuzz-spec tiny --fuzz-data-path /tmp/fuzz-data \
  --fuzz-sock-path /tmp/fuzz.sock --fuzz-log-level debug
```

The `fuzz` command activates the same built-in policy without requiring `JAM_FUZZ`
or policy files. `--fuzz-spec`, `--fuzz-data-path`, `--fuzz-sock-path` and
`--fuzz-log-level` override `JAM_FUZZ_SPEC`, `JAM_FUZZ_DATA_PATH`,
`JAM_FUZZ_SOCK_PATH` and `JAM_FUZZ_LOG_LEVEL`, respectively. Omitted flags keep the
captured environment value. Spec, data path and socket path must be supplied by
one of these sources; logging otherwise uses the ordinary default. A general
`--log-level` filter takes precedence over the conformance logging threshold.
The explicit-policy `serve-fuzz` and `serve-fuzz-preset` commands accept these
same environment overrides. Help identifies every mapping.

## PVM execution

`--pvm-backend jit|interpreted|polkavm-interpreted|polkavm-compiled` selects the guest engine for
application and nested invocation. The default `jit` uses our ARM64 native fragments on supported
macOS/Linux hosts, retaining our checked interpreter for unsupported platforms, instructions,
executable-storage refusals and native cache limits. `interpreted` forces our interpreter even
when the binary contains JIT support.

Build optional PolkaVM support with `make PVM_POLKAVM=1`. Explicit PolkaVM requests never switch
to our engine: missing builds/platform/sandbox capabilities produce a startup refusal. The pinned
compiler currently requires qualified Linux x86-64; its interpreter also supports ARM64. CI
comparisons use PolkaVM interpreted only for now. Startup logs state the requested mode and
fallback policy; prepared-owner diagnostics expose actual native activity without hot-loop logging.

## Node logging

The default `info` level prints timestamped startup identity/version/platform and selected role,
chain, database and service endpoints, followed by network/import/rejection activity and shutdown.
A foreground server reports peers, known local head, traffic and request counts every five seconds.
An unknown peer tip is shown as unknown; this is never a claim that the node is caught up.

`--log-level warn` keeps warnings and errors; `--log-level off` disables queued diagnostics.
Component filters remain available, for example `--log-level info,network=warn`.
Times use UTC (`Z`). Command results and the stdout readiness marker remain independently observable.
